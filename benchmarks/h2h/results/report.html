HeatherDB Head-to-Head

One HeatherDB process ran 5 enterprise workloads, each against the specialist system it would replace, on the same public data, splits and metrics. It matched or beat the incumbent on 3 and fell short on 2. Running all 5 costs 5.0x less per month than the specialist stack: one system to operate instead of 6.

What selective attention changed

Selective attention lets the memory learn which features and which moments to weigh, from prediction error, while data is written: each row is predicted before it is stored, and the miss teaches the attention. Same engine, same data; the only difference is the database setting.

Learned recency, relative to the newest item (lags 1, 2, 3-4, 5-7, 8-12, …): 1.00, 0.78, 0.60, 0.42, 0.29, 0.18, 0.10, 0.06. It started flat; nobody set a decay.

Remaining gaps

  • Fraud precision. PR-AUC 0.199 against LOF's 0.485 (ROC-AUC is level or better). The read scores raw distance to normal; LOF also corrects for local density. The fix, a spread per memory location, reached PR-AUC 0.500 in the prototype and is the next engine change.
  • Recommendations. NDCG@10 0.053 against ALS + recency (time-decayed confidence)'s 0.062 (85%). Learned recency closed most of the gap; what is left is the item code, a fixed random projection where ALS learns item vectors. With ALS's item vectors the same read reached 0.093 in the prototype, so codes the memory learns itself are the next lever.
  • Cost per scored row. Search is now faster than Qdrant (1.9 ms against 4.3 ms p50), but per-row scoring still costs more than a fitted model's: a propensity recall 1.0 ms against 0.8 µs, because the read scans every stored row, exactly, on every request. Fine for interactive use; batch scoring of millions of rows needs an index. The cost model sizes by memory, so at high query volume HeatherDB needs more CPU than shown.

Method

  • Public datasets, downloaded from their canonical sources; a SHA-256 fingerprint of the exact arrays is recorded per run.
  • HeatherDB is used only through its public HTTP API, with authentication on. Incumbents use library defaults or standard settings.
  • Qdrant runs as the real server in Docker. The other incumbents run as separate Python processes, each measured alone.
  • One machine: macOS-26.5.1-arm64-arm-64bit, Apple M4, 16 GiB. Engine heather 1.0.0 at v1.0.0-6-ge5dfbb2-dirty (feat/selective-attention).
  • Not modelled: staff time to run each system, network between services, high availability and replicas.
