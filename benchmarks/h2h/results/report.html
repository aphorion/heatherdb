HeatherDB Head-to-Head

One HeatherDB process ran 6 enterprise workloads, each against the specialist system it would replace, on the same public data, splits and metrics. It matched or beat the incumbent on 6. Running all 6 costs 6.0x less per month than the specialist stack: one system to operate instead of 7.

What the engine changes did

Selective attention (propensity, recommendations) lets the memory learn which features and which moments to weigh, from prediction error, while data is written: each row is predicted before it is stored, and the miss teaches the attention. Novelty (fraud) scores a transaction against how its nearest stored normals sit among themselves, not by raw distance, so rare-but-legitimate activity in sparse regions stops looking like fraud. It is the local outlier factor computed inside the memory: it ties LOF at the same neighbour count (50) and beats LOF at its default (20). Learned symbols (propensity, recommendations, access control) replace hand-encoding: ids and categories are written as values, and the same prediction error that teaches attention moves a small code per value, so a rarely seen value borrows from the values that behave like it. Remaining gaps

  • Cost per scored row. Search is now faster than Qdrant (2.1 ms against 3.7 ms p50), but per-row scoring still costs more than a fitted model's: a propensity recall 4.3 ms against 1.0 µs, because the read scans every stored row, exactly, on every request. Fine for interactive use; batch scoring of millions of rows needs an index. The cost model sizes by memory, so at high query volume HeatherDB needs more CPU than shown.

Method

  • Public datasets, downloaded from their canonical sources; a SHA-256 fingerprint of the exact arrays is recorded per run.
  • HeatherDB is used only through its public HTTP API, with authentication on. Incumbents use library defaults or standard settings.
  • Qdrant runs as the real server in Docker. The other incumbents run as separate Python processes, each measured alone.
  • One machine: macOS-26.5.1-arm64-arm-64bit, Apple M4, 16 GiB. Engine heather 1.0.0 at v1.0.0-8-g4a32470-dirty (feat/selective-attention).
  • Not modelled: staff time to run each system, network between services, high availability and replicas.
